# 学习设计与质量标准

## 从成果倒推

把“了解某主题”改写成可观察的任务，例如“能比较两个方案并解释取舍”“能独立完成一次操作”“能判断一个反例为什么不成立”。每个模块只承担必要的学习目标，并注明先修知识。

大纲包含：模块、可观察目标、先修要求、对应讲义/来源、练习、通过标准。默认短课程；目标需要更多篇幅时扩展，不承诺固定天数或把页数当质量。

## 单元骨架

1. 要解决的具体问题，以及读完应能做什么。
2. 所需概念与机制；术语第一次出现时解释。
3. 一个完整案例，写明输入、推理过程、结果与边界。
4. 一个常见误解或反例，说明何时原规则不适用。
5. 练习：必要时从回忆、应用递进到迁移，不必每单元机械凑齐三类。
6. 答案或评分标准，注明依据和允许的其他解法。

用户熟悉基础时压缩入门说明，把练习放在真实决策或任务上。用户要求考试备考时优先覆盖考纲；没有考纲就标记覆盖范围假设。

## 来源与编写内容

- 官方文档、原始论文、原始数据优先，按任务适用性选择，而非一律堆链接。
- 每条关键事实关联实际阅读过的来源。资料过时、无法访问、存在争议时写明。
- 自编案例标“教学示例”；推导或建议标“推断/建议”，不伪装成引用原文。
- NotebookLM 引用了我们的讲义，只证明它从讲义取材，不构成独立事实验证。关键事实回到原始来源核查。
- 上传的讲义与参考资料使用明确名称，例如“讲义 M01”和“原始资料 R01”。不把生成的摘要混入原始证据清单。
- 尊重资料的访问权限与版权。不为了生成课程而下载未经授权的完整教材或绕过付费墙。

## 生成指令模板

把模板中的字段替换后保存到本次课程 `prompts/`。课程大纲可作为来源；行为指令放在生成 prompt，不靠给来源起“系统指令”之类的名字控制模型。

```text
受众与基础：{audience}
学完要能做：{observable_outcomes}
语言：{language}
覆盖模块：{selected_modules}
使用来源：{selected_source_titles}
按照课程大纲组织，但不要省略关键先修知识。
每个模块给出问题、解释、带推理的案例、边界、练习。
区分来源事实与教学示例；对关键事实保留可追溯的引用。
来源不足或相互冲突时明确指出，不补造结论。
题目检查应用能力；为每题提供答案、解释和对应学习目标。
```

生成测验时，额外注明题量只是期望，实际题量和内容须下载后核验。生成音频时，指定重点与讲解风格；音频不是完整教材，不能保证逐字朗读、精确时长或全部知识点覆盖。

## 完成标准

| 检查项 | 验证方式 |
| --- | --- |
| 目标覆盖 | 每个目标能指向讲解位置和练习 |
| 先修顺序 | 练习使用的概念已讲解或明确要求预先掌握 |
| 事实依据 | 关键定义、数字和条件能追溯到实际读取的来源 |
| 答案一致 | 答案能解题，解释与讲义不冲突，开放题有评分标准 |
| 产物对应 | notebook、source、artifact ID 与本次记录一致 |
| 可用性 | 文件非空、格式正确、可打开；按产物类型阅读或播放检查 |
| 交付诚实 | 清楚区分本地完成、云端生成、内容检查与未完成部分 |

写入实际检查结果和证据，不预填“全部通过”。
